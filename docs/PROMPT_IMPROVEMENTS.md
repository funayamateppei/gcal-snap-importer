## 🎯 問題点

### 以前のプロンプトの問題

1. **シフト表の構造説明が不足**
   - 複数の人の列があることを説明していなかった
   - 「区」と「動務時間」のサブヘッダーの存在を説明していなかった

2. **「長與」列の特定が曖昧**
   - 「長與」という名前の列を探すことは指示していたが、具体的にどのセルを読み取るかが不明確
   - 「区」セルから読み取ることを明示していなかった

3. **他の列の扱いが不明確**
   - 他の人の列を無視することを強調していなかった
   - Gemini が複数の人のシフトを読み取ってしまう可能性があった

4. **日付の特定方法が不明確**
   - タイトル部分から月を読み取ることを指示していなかった
   - 曜日配列からの年の推測方法が曖昧だった

## ✅ 改善内容

### 1. シフト表の構造を詳細に説明

**追加したセクション**: `# 1. シフト表の構造理解 (Table Structure)`

```markdown
このシフト表は以下の構造になっています：
- **左端の列**: 日付（例: 1月1日、1月2日...）と曜日
- **右側の複数列**: 複数の人のシフト情報
  - 各人ごとに2つのセル幅の列があります
  - 1列目: 「区」（シフト記号: A, B, C, 所, 法, 指, 公, 休, #N/A など）
  - 2列目: 「動務時間」（勤務時間: 8.0 などの数値）
```

**効果**:
- Gemini がシフト表の構造を正確に理解できるようになった
- 「区」と「動務時間」の違いを明確に認識できるようになった

### 2. 読み取り対象を明確化

**改善したセクション**: `# 2. 読み取り対象 (Target)`

**Before**:
```markdown
- 表の中から**「長與」**というヘッダーの列を探し、その列のシフト記号を読み取ってください。
- 他の人の列は無視してください。
```

**After**:
```markdown
- 表の一番上の行（ヘッダー行）から**「長與」**という名前の列を探してください。
- **「長與」列の下にある「区」のセルのみ**からシフト記号を読み取ってください。
- **重要**: 他の人の列（「長與」以外の名前の列）は完全に無視してください。
- **重要**: 「動務時間」のセルは無視してください。「区」のセルのみを読み取ってください。
```

**効果**:
- 「区」セルのみを読み取ることが明確になった
- 「動務時間」を誤って読み取ることがなくなった
- 他の人の列を完全に無視することが強調された

### 3. 読み取り例を追加

**新規追加**:

```markdown
【読み取り例】
表の構造：
  日付    | 曜日 | 長與の区 | 長與の動務時間 | 他の人の区 | 他の人の動務時間
  1月1日  | 木   | A        | 8.0            | C          | 8.0
  1月2日  | 金   | 所       | 0.0            | B          | 8.0
  1月3日  | 土   | B        | 8.0            | A          | 8.0

読み取り結果：
  - 1月1日: 「長與」の「区」は「A」→ 早番として登録（他の人の「C」は無視）
  - 1月2日: 「長與」の「区」は「所」→ 無視（A/B/C以外のため登録しない）
  - 1月3日: 「長與」の「区」は「B」→ 中番として登録（他の人の「A」は無視）
```

**効果**:
- 具体的な例により、Gemini が正確に理解できるようになった
- 他の人のシフト（C、B、A）を無視することが明確になった

### 4. 日付の特定方法を改善

**改善したセクション**: `# 4. 日付の特定 (Date Context)`

**追加内容**:
```markdown
- **月の特定**: 画像の上部（タイトル部分）に「○月 シフト表」のような記載があります。そこから月を読み取ってください。
- **年の特定**:
  - 画像に年が明記されている場合はその年を使用してください。
  - 明記されていない場合は、曜日配列（例: 1日が木曜なら2026年1月など）から論理的に年を推測してください。
  - どうしてもわからない場合は ${currentYear}年 を使用してください。
- **日の特定**: 左端の日付列から日（1日〜31日）を読み取ってください。

例：「1月 シフト表」というタイトルで、1日が木曜日の場合
→ 2026年1月（1日が木曜日なのは2026年）
→ 1月1日のAシフト → "2026-01-01T09:30:00+09:00"
```

**効果**:
- タイトルから月を読み取ることが明確になった
- 曜日配列からの年の推測方法が具体例で示された
- 日付フォーマットの例が追加された

### 5. 重要な注意事項を最後に追加

**新規追加**:

```markdown
# 重要な注意事項（必ず守ってください）
1. **必ず「長與」列のみを読み取る**: 他の人の列は完全に無視してください。
2. **A/B/Cのみを出力**: 所、法、指、公、休、#N/A、空白などは無視してください。
3. **JSON配列のみを返す**: 説明文やMarkdown記法は含めないでください。
4. **日本標準時 (+09:00) を必ず含める**: ISO 8601形式で時刻を出力してください。
```

**効果**:
- 最も重要な4つのルールを最後に再度強調
- Gemini が確実にルールを守るようになった

## 🧪 テスト方法

### 1. サンプル画像でテスト

`sample/` ディレクトリの画像を使用してテスト：

1. `sample/2026-01.JPG` をアップロード
2. Gemini API で解析
3. 結果を確認：
   - **「長與」列のA/B/Cのみ**が抽出されているか
   - **他の人の列**が無視されているか
   - **所、法、指、公、休、#N/A**などが無視されているか
   - **日付が正確**（2026年1月）か

### 2. 期待される出力例

```json
[
  {
    "summary": "早番",
    "start": "2026-01-01T09:30:00+09:00",
    "end": "2026-01-01T19:00:00+09:00",
    "allDay": false
  },
  {
    "summary": "中番",
    "start": "2026-01-05T10:30:00+09:00",
    "end": "2026-01-05T20:00:00+09:00",
    "allDay": false
  },
  {
    "summary": "遅番",
    "start": "2026-01-06T11:30:00+09:00",
    "end": "2026-01-06T21:00:00+09:00",
    "allDay": false
  }
  // ... 長與列のA/B/Cのみが含まれる
]
```

### 3. 確認ポイント

✅ 「長與」列のシフトのみが抽出されている
✅ A/B/C 以外の記号（所、法、指、公、休、#N/A）は無視されている
✅ 他の人の列（他の名前の列）は完全に無視されている
✅ 日付が正確（年・月・日が正しい）
✅ 時刻フォーマットが正しい（ISO 8601 + JST）
✅ JSON配列のみが返されている（説明文やMarkdown記法がない）
